## 一、整体印象

**优点**

- 设计 token 收在 `:root` 一处（7 个变量），改色成本低
- 布局克制：顶栏 + 双栏（任务 / 日志），1280px 居中
- 深色配色 + 等宽日志区，符合"运维面板"的气质
- 任务名、日志内容都过了 `esc()`，没有裸 `innerHTML` 注入

**核心问题**

> 它看起来像在监控，实际什么都监控不到。

状态胶囊永远是绿色的"运行中"，任务卡片永远只有配置、没有任何运行结果。

## 二、视觉体系

| 维度 | 现状 | 评价 |
|---|---|---|
| 背景 | `#0f1115` / 面板 `#1a1d24` / 卡片 `#22262f` | 三层明度差足够，但**只靠边框区分层级**，没有阴影，观感偏平 |
| 主色 | `#4f8cff` | 与深色背景对比好 |
| 语义色 | 成功 `#22c55e`、危险 `#ef4444`、警告 `#f59e0b` | 三个色饱和度不统一，绿色在深底上偏刺眼 |
| 圆角 | 14 / 12 / 10 三级 | 有规律；但 `.log-box` 用 10、`.modal` 用 14，略显随意 |
| 字体 | Segoe UI + 微软雅黑 / Consolas | 合理；但全站无字号 scale，20/17/15/14/13/12 六档是手写值 |
| 主题 | 只有深色 | 无 `prefers-color-scheme`，白天使用偏累 |

## 三、布局与响应式

```
.app  max-width 1280, padding 20
└ .topbar                顶栏，独立圆角卡片
└ .layout  grid 1fr 400px
   ├ .tasks-panel        任务列表
   └ .log-panel          实时日志
```

三个结构性缺陷：

1. **日志高度写死**：`height: calc(100vh - 180px)`。180px 是拍脑袋的偏移量，顶栏高度一变或窗口很矮时，日志区会溢出或被截断。
2. **两栏滚动割裂**：任务多了页面整体变长，右侧日志却固定视口高度，滚轮落在哪边体验完全不同。
3. **移动端只是"堆叠"**：`@media (max-width: 900px)` 后变单列，但日志框仍按 `100vh-180px` 算，手机上很可能超出一屏还没滚到底。

## 四、组件盘点

| 组件 | 实现 | 缺口 |
|---|---|---|
| 状态胶囊 | 圆点 + 脉冲动画 + 文案 | 文案**硬编码**"运行中"，后端挂了照样绿 |
| 任务卡片 | 名称 + 4 个 tag + 3 按钮 | 无"下次执行 / 上次结果 / 耗时" |
| 按钮 | primary / success / danger / ghost / icon | 无 **disabled**、无 **loading** 态 |
| 弹窗 | 遮罩 + 表单 | 无 ESC 关闭、无 `role="dialog"`、无焦点管理 |
| 开关 | 纯 CSS | `input { display:none }` → **键盘完全不可达** |
| 日志区 | 等宽 + 级别配色 | 无过滤、无搜索、无空态、无自动滚动开关 |
| 空态 | 只有任务列表有 | 日志区空的时候是一片黑 |

## 五、最要命的一点：数据到了前端但没用

后端 `/api/status` 返回三样：

```json
{ "job_count": 3, "next_runs": { "早报发送": "2026-10-24T08:30:00+08:00" }, "plugins": ["qq"] }
```

`app.js` 只用了 `job_count`：

```js
async function loadStatus() {
  const s = await api("/api/status");
  $("#jobCount").textContent = s.job_count;   // ← 只取了这一个
}
```

**`next_runs` 和 `plugins` 被直接丢弃**。而"下次几点执行""插件是否在线"恰恰是这个面板最有价值的信息。用户现在能看到的只有配置，看不到任何运行事实。

## 七、改进建议（按性价比排序）

### 第一档：约 1 小时，观感立刻不同

1. **状态胶囊接真数据**：轮询 `/api/status` 时顺带判断请求成败，三态渲染 —— 🟢 运行中 / 🟡 有插件离线 / 🔴 后端无响应
2. **任务卡片补事实信息**：`下次 08:30 · 上次成功 2 分钟前`
3. **「清空」改成真清空**（DOM + 提示"仅清屏"），或干脆改成「暂停滚动」

### 第二档：交互补齐

4. **按钮 loading 态**：点击 → 禁用 + 文案变"执行中…" → 结果 toast
5. **统一 toast 组件**替掉 `alert` / `confirm`
6. **日志区增强**：级别过滤、自动滚动开关、点击行复制

### 第三档：可维护性

7. 开关改 `input { opacity:0; position:absolute }` + `.switch:focus-visible` 描边
8. 弹窗补 `role="dialog" aria-modal="true"`、ESC 关闭、打开时 focus 第一个输入
9. 布局改 flex：`min-height:0 + flex:1` 替代 `calc(100vh - 180px)`

## 八、改版预览版做了什么

原型见同目录 `AnySender-UI-预览.html`（单文件，浏览器直接打开）。

| 原版 | 预览版 | 对应问题 |
|---|---|---|
| 状态胶囊硬编码 | 绿/黄/红三态 | U1 |
| 卡片只有配置 | 增加"下次执行 / 上次结果（成功·耗时·失败原因）" | U2 |
| 无统计 | 顶栏下 4 个指标卡 | U2 |
| 日志无过滤 | 级别筛选 + 自动滚动 + 点击复制 | U3/U7 |
| 开关键盘不可达 | `opacity:0` + focus-visible 描边 | U8 |
| 弹窗无 aria | `role="dialog" aria-modal` + ESC + 焦点归还 | U9 |
| 日志高度写死 | flex + `min-height` | 布局缺陷 1 |
| 只有深色 | 深浅双主题 | U12 |
| 按钮无 loading | 执行态自旋 + 禁用 | U4 |
| `confirm()` 删除 | 两步确认（再点一次） | U6 |

预览文件左下有"预览控制台"，可切换三种运行状态与深浅主题。
